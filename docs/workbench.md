# 桌面工作台与统一运行契约

2026-10-23 源码开发版。保留 Python + WebView2，采用 React + TypeScript + Fluent UI 工作台；没有引入远程遥测。旧安装包不会自动包含源码新增功能。

## 已落地的边界

| 层 | 当前实现 | 负责什么 |
| --- | --- | --- |
| ModelProfile | `model_registry.py` | 公开 2B / 8B 模型的固定仓库、revision、原生 adapter、平台与引擎矩阵；下载、官方 GGUF 校验与本机转换共用这些身份 |
| InferenceBackend | 注册表 + 现有 GUI Engine / llama / Chat Completions / Codex 连接 | 模型加载、上下文策略与推理；不授予动作权限 |
| ExecutionBackend | 共享 `ExecutionCore`、Cua / Android / 独立浏览器后端 | 授权范围、动作校验、交付、重观察与停止；工作台 Win32 执行入口已停用 |
| RunSession | `run_session.py` + 控制台 | 启动时固定模型、引擎、执行后端、操作范围、经验路径及数据去向；回包证实的引擎单独记录 |

Qwen 2B 与 GUI-Owl 2B 可以使用 Transformers 或 llama-server，仍各用自己的提示词和动作解码器。Qwen 8B 已统一接入 llama-server，使用官方 Q4_K_M + F16 视觉投影、Q8 KV 和 Qwen 规范化动作协议；复用现有文件，不要求重新下载或转换。MAI-UI 是手机模型的有限桌面实验适配，当前仅开放 Transformers。D-5970 继续走原有冻结连接；并未承诺任意模型可以共用同一个动作协议。

GUI 任务把所选引擎传到推理客户端与服务端双重核对。旧服务或引擎不符会明确拒绝，不会静默回退。llama 换模型前先校验新文件；历史摘要结束后恢复原模型，而不是固定恢复 GUI-Owl。32K 窗口、24K 摘要阈值和保留 4 轮的策略常量由注册表共享，界面不再宣称 llama 路径永久保留全部历史文本。

## 工作流与迁移

新增本地模型接入优先使用 **llama-server**，先核对官方权重身份、GGUF / 视觉投影支持和原生动作协议。未保存引擎配置时默认 llama-server；已保存的 `runs/local-gui/backend.json` 保留，不自动改动。MAI-UI 尚未实现 llama 路径，仍明确标为 Transformers 实验适配，不宣称已统一迁移。

- **任务工作台**：任务指令、模型、经验、范围与执行后端；首屏开始按钮。仅开始前确认一次任务和数据去向，随后连续执行；全局停止按钮跨页面保持可见，F9 保留。
- **模型与连接**：紧凑的本地服务状态卡、引擎兼容矩阵、文件缺失信息及加密 API 配置。模型卡片区分“已选择”与“运行中”，连接地址与 PID 收入可展开详情。只在工作台首次加载、点击右上角刷新或完成显式服务启停后更新；不定时轮询，不因窗口聚焦、切换页面而检测。状态显示上次检查时间，不代表持续监控。D-5970 从服务展示、模型选项和组件登记入口隐藏，已有文件、服务与历史记录不删除。选择卡片不会切换模型；未连接或探测失败不等于确认进程退出。文件存在不等于任务质量认证。
- **经验库**：「经验版本」统一展示 A/B/D、完整模型原文与手动选用；「旧版状态图」独立保留，不混进当前执行入口。
- **运行记录**：新任务持久化索引、增量时间线、逐轮观察、模型回答和执行回执；模型声称完成与独立验证分开呈现。
- **录制、版本反馈、提示词、组件和 RSI**：已正式接入 React，包含 OpenCUA / WAA、讲解审核、阶段证据、反馈草稿与版本确认、组件安装/下载、提示词、API 清除、显式检查点恢复和 RSI 候选审查。本机 OpenCUA 仍不支持语音，WAA 才提供示范讲解。

工作台不再加载 iframe、旧页面或“兼容工具”弹窗，消除了旧页初始化后再切换样式的闪屏路径。离开页面不会卸载录制会话或丢弃表单草稿。`/legacy` 仅保留为手动访问的历史入口，不参与新导航。

没有转换或删除已有 Trace、经验、权重、反馈版本或旧日志。旧安装程序不会自动升级；开发版需退出后重新打开以加载新 Python 后端。旧 GUI 模型服务也需重新启动，才能支持新引擎核对契约。

## 回收站与编译边界

侧栏「回收站」统一列出原始录制、经验版本、任务包、候选反馈、人工反馈和运行记录。移入后从正常列表移除；正在选择的经验会取消选择。可逐条查看归档、恢复、再次确认后永久删除；不自动清空。恢复保留原 ID 和原始文件，不覆盖同名资产，不自动选中经验或启动任务。

Windows 文件占用时，先完整复制并逐文件校验 SHA-256，再标记为待清理并隐藏。清理前再次核验，损坏副本、原位置新增或变化的内容均拒绝删除；占用未解除时禁止永久删除安全副本。人工反馈恢复还核对移除后的任务文件版本，防止向已修改的任务自动挂回旧反馈。旧归档依据可验证的目录命名恢复；原位置不明的旧任务包或缺少版本证据的旧人工反馈需人工核对。

原始录制、已编译经验与运行审计是独立资产：移除录制不会级联删除已编译结果或运行历史。录制面板保留的完成记录会明确提示这一点。

目前 OpenCUA 录制支持本地确定性「原始证据 A」「精简序列 D」和 Codex「Agent 编译方法 B」。B 使用已确认的 Markdown Procedure 提示词，不复用旧状态图输出。「组合证据 C」从具体 B 版本生成，复用同一 Procedure 和其冻结 A 证据，不调用模型。旧 Windows / WAA Trace 的语义编译仍独立保留；更换执行模型不等于启用新的编译方法。

经验库默认只显示每份经验的当前版本，任务参考选择器也只列当前版本。「版本历史」可查看所有旧版本；当前版本卡片的「查看版本历史」展示这份经验的完整历史。卡片和详情保留生成时间，列表按新到旧排列。新产物保存带时区的生成时间；旧产物不回填或改写，只以明确标注的「旧版文件时间」作为参考。时间与来源只进入索引/审计元数据，不改变模型输入。

没有显式保存归属的旧经验，按同一来源和父子修订关系识别版本，不按显示名称合并；不同表示与不兼容的来源范围分别管理。首次读取旧经验库时，每组最新已发布版本成为当前版本。新提炼结果在保存时选择归属：作为已有经验的新版本，或建立新的独立经验。草稿不会替换当前版本；重复保存已经发布的草稿也不会撤销回滚。R 实验候选继续保持原有独立审查流程。

「成为已有经验的新版本」需要选定范围匹配的当前方法 B，保存后替换这份经验的当前版本，旧版进入历史。「成为新的独立经验」另起版本历史，原经验的当前版本不变，两份经验可分别进入自动检索。存在明确关联时默认接续该经验；没有明确关联时默认独立保存，也可主动选择要更新的已有经验。更改保存方式或接续目标后需重新核对；如果目标当前版本已变化，后台会拒绝过期保存。一次草稿只能按一种归属入库，重复提交不会改换归属。

在历史版本中打开「查看模型原文」，核对后可「回滚为当前版本」。确认绑定所查看的正文和当时的当前版本；版本已经变化时须刷新后重新确认。回滚持久保存于 `trace-library/.versions.json`，不移动或改写任何版本文件，旧运行仍引用实际使用的原版本。历史版本不自动删除；当前版本被手动移入回收站或文件损坏时，不会自动启用更旧版本。运行或编译期间禁止回滚。

重复生成按「同一原始录制 + 同一种表示」检查，不按显示名称去重，A/B/D 分别判断。后端先返回已有版本和确认提示，只有再次提交明确确认才写入新版本；取消确认不创建产物或启动 Agent。已移入回收站的版本不计为当前可用版本。旧版本通过 manifest 的来源路径识别，不凭同名猜测。旧语义编译重复调用也需要确认，并明确说明它会在已有任务包重新生成语义层。界面更新或并发点击不能绕过后台检查。

新版工作台的录制、编译、删除/恢复、设置和实验确认统一使用应用内对话框，不再调用浏览器 `window.confirm`。重复编译以可滚动列表列出已有版本、生成时间和短 ID；默认焦点在取消，Esc 或点击遮罩也只取消。永久删除以独立危险样式提示。手动访问的 `/legacy` 历史页面不在本轮界面重设计范围内。

### 原始证据 A：生成、审查与发送

完成官方动作整理的 OpenCUA 录制可直接「生成原始证据 A」，不调用 Compiler 或模型。独立版本保存原始事件、官方完整/展示动作的原文字节副本，以及完整截图索引和所有可用 PNG 副本；原录制移入回收站不影响已生成经验。时间和源录制身份留在审计元数据中，不混入模型文本。

新生成的 A 使用 `trace2task.A.action-evidence.v2` 格式。模型侧文本 `model-input.txt` 复用 **D 的同一份确定性动作投影**：原示范名称、屏幕尺寸、按顺序排列的 `actions`（原始动作描述、秒级持续时间、可见子动作和点击坐标）。仅为顶层动作补充选中图片的 `before_image` / `after_image` 引用，`image_ids` 对应附件顺序。不做语义摘要、动作修复或最终输入文字推断，也不补入 D 未包含的低层事件。

原始事件与完整/展示动作 JSONL、完整帧索引、路径、视频时钟、哈希等仍完整保存在审计归档，**不再拼进新 A 的模型文本**。图片附件按可用历史帧的时间顺序等距选择最多 **8 张**，包含首尾，不足 8 张全部选取；具体选中 ID 与规则冻结在版本内。缺图或未选图片不在动作中挂引用，近似对齐不表述为严格前态或成功证明。其余截图仅存档，不冒充模型已看到的像素。

「查看模型原文」直接展示完整运行文本、实际选中附件（可打开完整原图）、哈希、原始证据文件和未发送图片索引；历史 JSON 若生成了紧凑运行视图，归档原文另行折叠保留。读取 A 文本、图片及其他归档成员时验证哈希并限制文件边界。用户可手动把 A 或 D 用于新任务，不自动切换经验或扩大执行权限。

旧 `raw-evidence.v1` 版本仍按其冻结内容读取，不自动改写；界面明确提示其包含原始日志和索引。如需精简格式，从原始录制重新生成 A 并确认新增版本，再审查和选用。

Codex / 视觉 API 在首轮传送完整文本与选中的历史图片，并明确区分当前截图；正常后续轮次沿用会话，在图片清理/线程重建时重新附加冻结的 A 图片。本地 Transformers / llama 将这些历史图片与完整经验文本作为固定会话前缀，历史观察压缩或清图不删除它们；真正提交的图片顺序、历史帧 ID 与服务输入都入审计。容量不足明确报错，不静默降级成纯文本 A，也不裁掉部分经验。D-5970 的冻结输入协议仍不接受经验。

### Agent 编译方法 B

入口为「经验库 → 原始录制 → Agent 编译方法 B」，使用「编译与反馈模型」中选择的 Codex 模型及思考强度。应用内确认会说明动作与最多 8 张历史截图将发送给 Codex。固定提示词见 `procedure_prompt.py`，版本为 `procedure-markdown-2026-10-08`，采用已确认的完整规则，不要求 JSON、status、audit 或证据索引进入正文。

编译前冻结与 A 相同的动作投影和选图规则，不自动创建可见的 A 条目。Agent 只编译历史证据，不执行桌面动作；返回纯 Markdown 方法名称、用途、可选输入参数与有序步骤，条件、结果检查和具体不确定性融入对应位置。`model-input.txt` 原样保存 Agent 返回的 Procedure，不注入来源路径、哈希等元数据；执行时只发送这份全文，不附编译提示词、原始动作或历史截图，也不自动替换参数。审计区可查看完整编译提示词、输入、实际选中图片、模型与版本。

B 沿用独立版本、时间展示、同源同表示重复确认、手动选用及回收站恢复。后台任务与编译的输入/输出进入运行记录，完成后可直接打开对应 Procedure。格式校验仅确认 Markdown 基本结构，不证明方法语义正确；空输出、JSON/代码围栏、缺少方法用途或有序步骤、编译异常与取消都不会发布可用 B。已取得的输出及冻结证据保留供审计，失败目录没有发布 header，不会作为经验使用；不自动重试或覆盖旧版本。

### Codex 订阅模型

执行、编译和修订选择器从当前安装的 Codex App Server `model/list` 读取模型顺序、显示名称、默认值、截图支持及每个模型的推理强度，处理分页并排除隐藏条目。切换模型时保留兼容的强度，否则采用该模型默认值；启动前再次核对所选组合。目录缓存 5 分钟，可点击「刷新订阅模型」立即重读。读取失败时显示原因，保留上次目录并标为过期，不用写死的列表冒充当前可用模型。目录可见性不代表已完成推理或任务质量验证。协议依据：[Codex App Server 模型发现](https://developers.openai.com/codex/app-server#list-models-modellist)。

### 从 Agent 运行提炼经验

在「运行记录」选择已结束的 Agent 执行任务，点击「提炼为经验」进入「经验手稿」。左侧回看来源、真实交付轮次与最多 8 张首尾等距取样的历史截图；右侧先展示方法结构和将发送的逐轮证据简表。只读取已有记录，不重新操作设备。

点击后立即展示本机读取状态；预检失败时，原因与「重新读取」按钮直接显示在手稿窗口，不只放在页面顶部。预检成功前不能生成，重新读取失败也不能沿用旧预览。运行提炼和固定改进器均已取消程序内的 160 KB 文本限制与 200 轮读取上限；JSON 输入统一采用紧凑排版，保留全部轮次的判断原文、适用的方法内容和人工说明。不自动摘要、分段调用或截断；所选模型的实际上下文容量仍有效，模型/服务拒绝会明确报错，失败不发布草稿或候选。图片、来源校验与真实执行预算不受影响。

点击「生成经验草稿」后，由所选 Codex 编译模型按阶段整理：进入条件、操作、可观察反馈、进入下一阶段或分支的条件，不固定章节名称或步骤数量。正文独立作为新任务的补充信息，直接写全需要保留的流程与条件，不使用“旧方法”“父方法”“本次未覆盖”等模糊指代。超出模型容量会报错，不静默截断。草稿保存在运行目录，与经验库分开；停止、异常、缺少基本方法结构或包含来源报告的输出不会发布可用草稿。

运行提炼与固定改进器将 `compiler-input.txt`（模型任务证据）和 `evidence/run.json`／`evidence/run-feedback.json`（本地审计）分开。模型输入不重复携带经验 SHA、逐轮 SHA、谱系 UUID、归档路径和校验清单；原父版本身份、来源哈希、原始回执及图片校验仍留在本地，生成确认绑定完整源记录与实际输入，保存仍核验冻结文件。旧草稿和经验不重写。

运行经验使用 `trace2task.method-evidence.v2`：所有轮次变为简表，保留模型判断原文、操作语义、交付状态、解析差异、部分交付和异常；未执行计划不会记为已交付。普通坐标、移动/等待毫秒数、默认左键、重复标准回执和标注笔画坐标留在本地。方向、右键、按键、输入内容与长按时长等有操作意义的信息保留；不能无损解析的模型回答保持原文。首尾等距取样的观察和人工附图按哈希去重，以短图片编号关联；缺图明确标记，不推断未提供的画面。人工文字、状态和接管前后图仍提供，重复接管说明只出现一次。独立 R 改进实验仍沿用原有证据投影契约。

完成后点击「审阅经验草稿」。正文只写方法与具体适用边界，不含轮次引用、修订报告或单独的人工干预报告；来源、贡献、继承关系与差异继续单独归档。送达、视觉复核与独立成功验证仍严格区分。勾选核对后才能「保存到经验库」，后台验证来源和草稿哈希，发布独立的文本方法 B。仅确认保存仍属 Trace Compile，不是新的人工修改实验条件；不覆盖源运行、不自动选用经验、不启动新任务。重复提炼需再次确认，旧草稿可从来源页重新打开；修改旧草稿时从归档证据重建新输入，原草稿保持不变。

运行来源的 B 显示来源标记，不冒充人类示范编译，也不生成组合证据 C。Android 可手动选用同一授权应用运行提炼的 B，由普通 Agent 执行；不同应用、不同操作范围和 MobileForge 路径会明确拒绝。经验只提供参考，不扩大当前任务权限，历史坐标与旧画面不代表当前状态。

### 组合证据 C：同一 B + 对应 A

入口：「经验库 → 经验版本 → 选定 B 卡片 → 生成组合证据 C」。确认框显示具体 B 的名称、时间与 ID，不从同名版本中自动挑选。C 按所选 B ID 判断重复；取消不创建产物，确认生成新版本也不重新调用 Compiler。

`trace2task.C.combined.v1` 独立归档 B 的逐字节 Procedure（`procedure.md`）及 B 编译时冻结的 A 证据目录。归档的 `model-input.txt` 仅在两份原文外添加分段标记；不摘要、改写或重新编译。执行发送完整组合内容（仅 A 的 JSON 排版空白可按下文规则无损移除）和 A 中原已选中的最多 8 张图片，不重新选图，不发送 B 的编译提示词或审计元数据。原录制或 B 移入回收站后，C 仍可独立使用和恢复。

C 沿用 A 的 Codex/API、本地模型图片输入通道、上下文预算与执行确认，不扩大动作权限；B 继续只发送方法正文。生成和读取验证来源及图片哈希，最后发布 header；缺失或篡改的来源不发布可用 C。预览展示实际完整模型输入、附件及来源 B ID，只有显式「用于新任务」才选用。

### 运行后方法改进 R（固定改进器实验）

主线保持「人类示范 → Trace Compile B → 执行反馈 → 候选 → 审查 → 显式试用」。
R 是独立的 `trace-compile+fixed-updater` 条件，不覆盖原始示范、B 或 C，也不混入 B/C 表示对照。
它支持多代方法更新，但改进器提示词仍固定；不是 Hyperagents 式的改进器自改进，尚无质量提升结论。
已有远程 RSI 练习和候选审查继续独立保留，本入口不启动远程 VM，也不绑定某篇论文的引擎。

1. 用 B（或已经获准试用的 R）完成一次普通任务，再展开运行时间线中的「运行后改进 · 固定改进器」。
2. 确认将父方法、本次指令、逐轮反馈投影与最多 8 张归档观察交给所选 Codex。一次请求只启动一个改进 turn，硬超时 600 秒；没有执行工具、自动重试或自动继续练习。
3. 在经验库比较父方法和候选全文，展开完整改进输入、选中图片与来源。选择「审查后允许试用」或「拒绝候选」；不可覆盖的审查决定绑定候选清单 SHA-256。
4. 允许试用只开放显式选择，不自动开始任务或替换当前经验。仍使用现有授权、动作确认和停止机制。需要回退时重新选择原 B 或先前 R。

新运行同时记录启动选择的经验身份/哈希，以及实际交给模型的经验哈希。旧记录没有这些证据时不补写、不猜测，须完成一次新运行。预览、未交付操作、来源哈希不匹配、未结束或已回收的运行，以及已知前后台输入故障均不能生成候选。只接受 B/R 来源；C 保留其「同一冻结 B + A」定义，不从 C 暗中生成另一份 B。

`trace2task.R.procedure-evolution.v1` 保存父方法全文、反馈投影、原始逐轮记录的哈希、选中图片、完整改进请求/回答与谱系。反馈文本与源轮次数不再设置固定程序上限，不静默摘要或截断；单图 10 MB / 总图 40 MB 的图片限制保留。图片按时间等距最多选 8 张，缺失与未选中明确标记。原始模型请求留在运行归档，不整体转发给改进器。取消、异常、无变化或冻结文件被篡改均不发布候选；发布后仍需单独审查。

格式检查与人工试用许可**不是独立任务验证**。下一阶段应接可重置环境的训练/验证/留出任务，并在相同总预算下比较固定 B、反思记忆、固定改进器、可变改进器。游戏只是验证环境，不能靠一次模型自报完成宣称胜率或递归改进能力提升。本轮自动化测试使用合成回执和替身模型，没有实际游戏成绩。

### 表示对照

这三个字母是之前讨论的**经验输入表示**，不是三个推理后端：

| 表示 | 内容 | 不包含或约束 |
| --- | --- | --- |
| A：丰富原始证据 | 源示范背景、动作/事件及关联历史截图与证据引用 | 不添加 Compiler 的语义方法；原档完整保留不等于每轮发送全部原始文件 |
| B：编译后的 Procedure | Compiler 从源示范提炼的 Markdown 任务方法，包括用途、可选参数、有序步骤，以及就地表达的条件、检查和不确定性 | 生成后冻结，不随当前执行在线改写；正文不含审计索引，也不附完整原始证据 |
| C：证据 + Procedure | 与 A 相同的证据，加上与 B 完全相同的一份冻结 Procedure | 不能为 C 再单独编译一份 B，否则混入编译差异 |

D 是无截图、无语义解释的确定性精简动作序列；N 是不提供示范的基线。所有条件另有当前任务和当前观察。A/B/C 已按上述规则接入，没有把旧状态图编译器直接更名为 B。R 单独标为运行后改进实验，不计入原始 A/B/C 对照。

### 模型输入的 JSON 排版

新生成的 A、D、B 编译证据、运行反馈、固定改进器反馈及自动经验检索请求统一使用紧凑 JSON；C 继承 B 冻结的同一份 A，不重新编译或改写父方法。本地清单和审计 JSON 保留可读缩进，它们不因排版而重复进入模型输入。

已保存的结构化 A／D 和 C 内的 A 后缀，在下一次加载时生成无损的紧凑运行视图；不迁移、覆盖或重写历史文件。只删除 JSON 字符串外的排版空白，不重新编码旧数字或转义，不改变键顺序、重复键、动作、字符串内容、前言及 B／R Markdown 正文。不能确认的旧格式原样保留。

「查看模型原文」展示实际运行文本，并可展开归档原文与双方 SHA-256。新运行事实保存 `experience_source_sha256`（归档）和 `experience_sha256`（实际输入）；逐轮回执、冻结经验快照及反馈编译使用后者，父版本校验同时核对前者。旧运行仍按其当时的原文哈希解析；未知哈希、来源变化和快照被改动仍拒绝反馈。历史模型输入查看不补写为新格式。

## 本地运行记录

每类任务（执行、录制、编译、修订）在线程启动前写入索引，不依赖页面轮询。任务回调持续写入状态与事件；读取历史接口不修改记录。已通过真实控制台回调 → SQLite → 重新创建后台 → HTTP 读取的隔离测试；测试未调用模型或发送桌面输入，也不向用户数据目录注入演示记录。

`runs/workbench.sqlite3` 保存运行摘要、带游标的事件与按轮读取的完整记录。事件采用 `trace_id`、`span_id`、时间、名称和 attributes 的简单结构，借鉴可观测性术语，但**不是宣称符合某个版本的 OpenTelemetry 导出规范**，也不连接监控服务。

前端通过 `/api/workbench/runs/{id}?after=...` 只取新事件。原始模型请求/输出在展开对应轮次时才读取，不在每次轮询中传输整段历史。React 按稳定轮次 ID 更新，不强制滚到日志底部，不重建已展开的全部记录。原有每次推理的取证归档仍保留。

展开「模型输入、输出与执行回执」后，先展示该轮记录中的输入原文，再显示模型输出与执行回执。本轮消息可直接复制文字；实际请求携带的历史消息和系统/开发者提示词单独折叠，推理参数等仍在完整记录中，不拼进输入正文。不二次摘要或裁剪消息内容，也不用当前任务/设置补写历史输入。

「查看该轮画面」在对应轮次卡片内原地展开/收起归档截图，可打开原图；不同轮次互不替换，不滚回顶部，轮询更新也保留展开状态。图片仅在展开时加载。运行时间线改为单栏，「本次运行事实」放在顶部折叠区，不再使用右侧共享画面面板。

本地模型按归档的附件顺序关联当前、历史和示范截图；新聊天调用记录本轮真实附件的本地路径，不改变发送给模型的请求。旧记录没有图片映射时明确提示无法预览，不用某张观察画面冒充所有附件。准备输入、缺失记录和已归档占位符分别标注。Codex 只展示本程序提交的该轮内容，服务端历史及内置系统指令未由接口返回，不宣称该视图包含完整服务端上下文。

重启后尚未结束的记录显示“会话中断”，不会自动恢复键鼠操作。迁移前的运行文件不自动导入索引或改写，仍在原目录可查。原始请求可能包含截图、任务文本和经验，数据保留策略由用户掌控，当前没有自动清理。

## Agent 按需加载记忆

任务入口的「参考经验」默认选中「自动选择」。同一个执行模型先通过 `search_memory` 查看已发布方法 B 的 ID、名称、用途摘要与历史结果，再选择 `load_memory` 加载一份全文，或 `skip_memory` 不加载；不替换执行模型，不读取未保存草稿，不自动生成或修改经验。手动固定 A/B/C/D/R 版本和「不使用经验」仍保留。自动选择首版支持 Codex / 视觉 API 通用代理，本地 GUI 专用模型和 MobileForge 不启用此协议。

每次任务最多检索两次、加载一份 B；每份经验只提供持久记录中的当前版本，包括用户回滚后选定的旧版。显式保存为独立经验的结果分别管理，即使共享来源或父方法也不会合并。历史版本需先在版本历史中回滚，再用于后续任务。Android 严格匹配授权包名，运行经验匹配操作范围；缺少来源范围的旧录制只进入桌面候选。检索结果是候选而非规则，Agent 可判断不适用。加载前后复核当前版本身份、目录、正文和清单哈希；已移入回收站、版本变化或非法请求会停止，不发送后续操作。记忆不扩大应用授权，F9、停止按钮、动作预算和时间预算仍有效。

选择阶段只发送检索到的摘要，只有选中方法后才发送其全文。选择完成后清空临时检索会话上下文，以同一模型、已冻结的方法和新截图开始操作。运行目录的 `memory/catalog.json`、`memory/selection.json` 和（已加载时）`memory/model-input.txt` 保留版本与选择依据；运行事实保留启动时的 `memory_mode=auto`，实际加载记录单独展示，不伪装成手动指定经验。此实现未进行任务成功率或经验效果对比实验。

选择模型只接收与适用性有关的授权范围、应用包名／窗口名称／页面 URL 及可用动作名称，不接收设备 serial、ADB 端口、transport/boot ID、窗口 PID/句柄、截图尺寸或执行路由。候选已在本地按操作范围和版本筛选，Android 另按授权包名过滤；不再逐条重复包名、表示、来源运行 ID、生成时间、完整谱系及 SHA-256；“未完成／未独立验证”等历史结果原文保留。检索历史只补充查询词和返回 ID，保留两次检索结果的可加载身份，不重复发送空参数与选择理由。用户任务、名称、用途、结果和查询词不做关键字清洗。

完整候选、原执行上下文与版本哈希仍保存在本地 `memory/catalog.json`，完整请求及理由仍在 `memory/selection.json`；模型输入查看展示真实发送的精简文本。原目录权限、同应用筛选、只加载已返回 ID、两次检索预算及加载前后哈希复核不变。仅新选择请求采用此格式，不改写旧运行或已保存经验。

### 使用经验后的反馈修订

“提炼为经验”现在区分无经验运行和使用经验后的反馈：后者把**实际使用的原方法内容、当前任务、模型判断、交付状态与选中观察**交给编译 Agent，输出完整修订草稿；父版本 ID/哈希留在本地校验与审计，不重复塞入模型正文。自动加载与手动选择共用来源核对；每个已交付回合必须携带相同的实际经验哈希。新版运行同时冻结 `experience/model-input.txt`；旧运行只有在版本身份、库中正文和回合哈希仍匹配时才可重新提炼。缺少身份或哈希不一致会明确拒绝，不静默退回独立编译。

编译提示词要求保留仍适用的步骤、仅据本次证据修正，未覆盖的步骤不得直接删除。保留的流程直接写全，正文不再写 `[父方法]`、`[第 N 轮]` 或反馈修订说明。编译输入仅删除父方法中已知的来源报告与引用，完整父方法仍在本地归档；网络或预算中断不自动当作策略错误。原样返回符合独立方法要求的父方法时记录 `revision_changed=false`，不声称产生改进。

草稿和已保存版本保留父经验副本、差异、根版本及代数。仍使用方法 B 的文本格式，但反馈派生版本显式标为 `condition=trace-compile+run-feedback`，不冒充原始示范编译，也不覆盖原版本。来源谱系 `lineage` 与保存归属 `versioning` 分开：独立保存不会删除来源证据，后续编辑或反馈修订也沿着独立经验自己的版本历史继续，不因最初的父方法重新并回原经验。用户核对保存后，结果才进入下一次自动检索；仅生成草稿不会进入候选。高级的独立 R 固定改进器仍保留，也能识别自动加载的实际父方法；它的审查规则不变。

### Android 运行中干预

Android 通用视觉代理的运行详情新增「运行中干预」：发送补充指令、请求暂停接管、填写说明并交还模型。必须等「已暂停 · 可以手动操作」后再动手机；交还时核对原授权应用并重新截图，丢弃未执行的旧计划与过期完成复核。原预算和 F9 始终有效，暂停不冻结游戏。MobileForge 暂不显示此入口。

干预文字、实际提交轮次和接管前后截图随运行留档，历史任务只能查看、不自动恢复；没有精确操作录制。提炼预览明确展示人工来源，并将对应文字和图片传给编译 Agent；保存后的经验标注人工辅助，保留实际父经验谱系，不声称自主成功或方法已改善。详见 [Android 接管语义与验证边界](android-backend.md#运行中追加指令与人工接管2026-10-23)。

## 全局回收站与批量移除

侧栏「回收站」统一显示原始录制、经验版本、旧版任务包、反馈及运行记录；旧回收站归档不迁移、不自动清空。经验库、录制示范页的已保存列表、运行记录均使用勾选和「批量移到回收站」，单项也通过同一入口处理。全选只覆盖当前显示的分类和筛选结果（运行记录为当前加载的最多 40 条），不会隐式选择未加载数据。取消确认不发送删除请求；部分失败会报告成功/失败数量并保留失败项的勾选，可单独重试。

运行记录采用 SQLite `session_trash` 标记，移除时保留完整摘要、事件与逐轮原文，重启后仍可恢复；确认永久删除只删除该运行的数据库记录，不删除关联目录中的截图、录制或经验。文件资产继续使用既有安全移动、冲突检测及恢复逻辑。任务执行、录制或等待讲解期间禁止这些删除/恢复操作。恢复不会自动启动任务或选用经验。
