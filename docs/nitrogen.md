# NitroGen 本机游戏模式

可从「任务工作台 → 原模式 → 本地模型 → NitroGen」启动。任务时间线显示每轮送入模型的截图、原始摇杆与按键预测、提交给手柄的动作，以及已完成批次的动作后画面。手柄回执表示执行器提交了输入，游戏实际效果可以对照前后画面检查。

「截图任务文字」可填至多 32 字。文字只画在送入模型的截图上，时间线保存该输入图；游戏窗口和动作后截图保持原样。此项用于实验，NitroGen 可能忽略截图中的文字。

在源码版 Trace2Task 的「模型与连接 → NitroGen」按窗口标题或 `.exe` 名称搜索，选择已打开的 Windows 游戏进程，再设置运行时长。游戏刚打开时，可以点击「刷新运行中的程序」。确认后，Trace2Task 启动项目作者提供的 `scripts/serve.py` 和 `scripts/play.py`，由官方 `GamepadEnv` 控制虚拟手柄。截图、模型预测和手柄动作都在本机处理。NitroGen 根据截图生成手柄动作，入口不接收文字任务，也不接入 Android/ADB。

执行器会激活游戏窗口，使用上游 DXcam 截图和 xspeedhack 游戏时序控制。游戏失去前台焦点、达到时限或按 F9 时结束，并尝试恢复正常游戏速度和释放虚拟手柄。上游要求 Windows 和 ViGEmBus，游戏需要支持手柄并允许该执行方式。

如果所选架构的 xspeedhack 文件缺失，执行器会使用实时模式，继续采用同一套截图、推理和虚拟手柄。动作在同一批内连续执行，手柄在每批结束和失焦时回中。游戏在推理期间照常运行。日志会标明实时模式及缺失文件。

启动前请先手动退出暂停菜单并进入可操作的关卡。官方默认禁用菜单键，模型可能一直停留在暂停画面。

《以撒的结合》是例外。启动前将游戏留在主菜单，启动后切回游戏。F5 用虚拟手柄下移菜单项，F6 确认，F7 返回。用 F6 确认「继续游戏」，再按 F8 让同一个手柄向右推一秒。看到角色移动后按 F10，将这个手柄交给 NitroGen。若角色未移动，可按 F9 停止。菜单绑定和测试不占用模型操作时长。

如果 Windows 未让执行器自动切到游戏，按工作台提示在 20 秒内切到该窗口。运行时长从第一次手柄操作开始计时。

实时模式下，运行中失去焦点会立即中断当前动作序列。切回游戏后会重新截图和推理，原动作不会接着执行。超过 20 秒未切回或耗尽任务时长，运行结束。

运行日志和上游生成的截图、视频、动作序列在数据目录的 `runs/nitrogen/<运行 ID>/`。窗口中的任务状态表示运行过程，任务时限并非游戏目标验收。

默认运行环境 `D:/Models/NitroGen`，可用 `TRACE2TASK_NITROGEN_ROOT` 改址。运行目录需包含独立的 `.venv/Scripts/python.exe`、官方 Git 工作树 `upstream` 和已核验的 `ng.pt`。安装时应使用支持本机显卡的 CUDA PyTorch，再在同一环境执行 `pip install -e <upstream>`。若本机已安装 ViGEmBus，可在安装 vgamepad 前设置 `VGAMEPAD_SKIP_VIGEMBUS_INSTALL=true`，避免安装器重复安装驱动。模型同时依赖 `google/siglip2-large-patch16-256`，缓存目录在运行环境的 `hf-cache`。启动器将上游 ZeroMQ 服务限制在本机回环地址，保留其推理和动作协议。
