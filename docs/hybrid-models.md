# 混合模型：Terra-guided v7

任务页选择「混合模型 · 独立指导与执行」。指导端可选 Codex 订阅或视觉 API（包括本地兼容服务）；执行端可选已接入本地模型、Codex 或视觉 API。两端独立选择模型、连接、密钥，使用独立会话。切换模式不再强制选择 Terra、low 或关闭经验。API 执行端使用通用单动作协议，本地专用执行端仍用原生协议。原模式保留原有执行方式。

## 当前指导提示词与 v7 来源

当前使用本地 `task-first-v2-notices` 指导提示词。指导模型根据任务目标和最新画面安排动作或子目标，在 `notices` 中转述当前阶段适用的经验、条件性提醒和明确限制。运行记录保存提示词版本和哈希。控制协议源自 4090 的 `terra-guided-other3-20261104-owl2b`（v7 / concise-v2）。

- 原始指导提示词、首轮与增量输入、原始动作 schema、配置及源文件：[证据目录](evidence/terra-guided-v7/provenance.json)。两个源文件均与服务器冻结 manifest 的 SHA-256 一致。
- 每任务一个指导会话，后续发送最新截图、交回原因和当前子目标，不重新发送完整总目标。
- 指导模型可先给出至多 12 条纠正动作，再交给主要执行模型。逐条执行、逐条截图并记入实际回执；人工干预、失效或拒绝后清空未执行队列。总预算与停止仍生效。
- 指导端和执行端各自使用同一任务内的连续会话，换阶段时继续沿用。Codex 续用会话，兼容 API 保留并提交消息历史，接近上下文上限时清理旧图。远程执行端每轮提交新截图，子目标或授权范围变化时补充更新，有新执行的指导动作时附上动作。
- 本地执行端读取当前子目标，按会话追加已确认的动作。指导动作以文字加入历史。llama.cpp 沿用引擎的前缀缓存，Transformers 沿用文本前缀缓存，GUI-Decisions 保留已执行动作文字且只读取当前截图。实际缓存命中取决于模型与引擎，运行记录会保存可用的缓存 token 数。
- 选择应用底层知识后，指导和执行会话均在首轮接收同一份知识。完整任务经验由指导端读取，执行端通过 `notices` 接收与当前子目标相关的内容。GUI-Decisions 的槽位接口每轮需要完整指令，服务在本地沿用首轮接收的知识。
- 工作台可在混合模式下调整总决策、指导次数、周期复查间隔和重复无变化交回阈值，默认分别为 120、12、24、3。总决策包含指导动作，任务总预算与停止控制仍有效。
- 动作使用当前截图的 `0..1` 坐标和所选 Android/Cua 后端的既有格式。服务器原文和原 schema 留作来源证据，当前运行协议带 `-local-actions-notices`。
- 指导动作的执行历史使用明确标注的本地 GUI 动作记录；本地模型原生系统提示词和已选择的推理服务保持现有配置。没有复制服务器权重或切换本地推理框架。
- 两端模型仍独立可选。Codex 和视觉 API 指导均保持各自任务会话，执行模型会话独立。

重新启动本工作区 Trace2Task。使用本地执行模型时也需重启其服务以加载连续会话协议。

## 采用的协议与参数

| 项目 | v6 行为 |
| --- | --- |
| 指导模型参考配置 | Codex 订阅 `gpt-6.1-terra`，`low`，单次等待 600 秒 |
| 最多本地决策 | 60 次，包括完成报告和无效决策 |
| 最多指导调用 | 8 次 |
| 周期复查 | 每 12 次执行决策 |
| 卡住检测 | 连续 3 次相同动作且操作前后截图哈希未变；仅画面不变不会触发 |
| 指导输入 | 总任务、当前截图、交回原因、当前子目标、最近 6 个先前子目标契约；不发送执行流水或剩余预算 |
| 指导输出 | `stage / continue / finish / blocked`，观察、目标、完成提示、约束、交回条件；模型不能设置预算 |
| 小模型指令 | 仅当前目标和全部先前子目标，按原顺序保留重复和无动作阶段；不包含总任务或指导元数据 |
| 换阶段历史 | 最近 2 组确已执行的原生动作及其操作前截图 |
| 阶段内历史 | 累积已执行动作文字，仅保留最近 2 张历史图，再附当前图 |
| continue | 仅周期复查时合法，契约必须逐项不变；不新增阶段、不重置历史 |
| 执行粒度 | 每次一条动作；批量回答拒绝并交回，未执行动作不进入历史 |

原模型的完成/提问/失败输出只触发交回。指导声明完成也不等于外部验收成功。模型或服务错误停止，不自动重试；上下文溢出不悄悄压缩或删除固定证据。

## 本地适配边界

这次迁移的是实测**指导提示词、字段契约、调度参数和历史策略**，不是服务器整个实验环境。

- 按用户要求继续使用已接入、可选的本地模型和其原生系统提示词/动作格式，没有下载或切换到服务器 Desktop131 权重。原服务器小模型是 Desktop131 贪心执行器。
- 支持 Cua 桌面/指定窗口及 Android；仍经过现有动作校验、设备/应用范围约束和停止机制。独立浏览器、MobileForge、D-5970 不支持此模式。
- GUI-Decisions / SlotRead 原生只接受当前图，保留动作文字历史；界面和运行记录明确标记 `current_only_slotread`。其他多模态本地接口支持两张历史图。不宣称 SlotRead 完整复现原图像历史。
- 本地没有服务器独立环境评分器。`finish` 后保留现有的新截图只读视觉复核，这一额外调用不属于 8 次调度指导；结果不能视为 OSWorld 分数，也不设置独立验证成功。
- 人工干预和手动/自动参考经验是可选的本地扩展：启用时会额外发送给指导模型并记录。普通单模型的自定义 Codex 提示词不混入 v6 指导前缀。
- 原首版的「8 动作 / 100 秒子任务预算」已由 v6 的 60/8/12/3 控制替换；Android 动作 `wait` 的 100 秒上限保留。用户设置的总动作/时间预算仍能提前停止任务。

运行记录包含协议名、控制配置、提示词哈希、实际指导模型、执行模型、指导次数、执行决策数和阶段数。原始订阅通信保存在 I/O audit，本地请求/回答保存在 `hybrid-local/`，运行 trace 记录指导、交回与历史继承。

需要重启本工作区的 Trace2Task 和本地模型服务。旧本地服务没有 `guided_history_v6` 能力时，会在发送截图前明确拒绝；不会静默退回旧策略。

验证包括原始文件哈希、提示词/schema 等值、历史隔离、continue、预算、重复动作、停止、真实服务组包（模拟推理）、共享执行循环和界面测试。未在这次迁移中执行真实云手机任务。
