# GUI-Decisions-2B 常驻本地服务

在“模型与连接”选择 **GUI-Decisions · 2B**，引擎为 `slotread`，点击“启动所选服务”。服务完成预加载后，新任务继续使用同一个模型进程。任务结束、停止任务或关闭工作台不卸载权重；“关闭 GUI 服务”或启动其他本地模型会终止所属推理进程并释放显存。

复用作者的 [LocalSlotModel](https://huggingface.co/infinitylogesh/GUI-Decisions-2B#in-process-with-transformers-no-server)，使用 Transformers、BF16、SDPA 和原生槽位解码。模型固定为 `c2cedfd0a5344ecaa058080555ddd4b85be3284d`，加载前核对模型、处理器和槽位配置的 SHA256。

部署默认位于 `D:/Models/GUI-Decisions-2B`，可通过 `TRACE2TASK_GUI_DECISIONS_ROOT` 指向同结构目录，需要 `.venv/Scripts/python.exe`、`model/` 和 `source/slotread/`。沿用此前已完成的独立官方部署及 Windows 兼容补丁，不向通用 GUI 环境安装或升级依赖。此模型不使用通用组件下载器。

## 服务和会话

- 继续使用受令牌保护的 `127.0.0.1:8768`、`/load`、`/predict` 和 `/cancel`。HTTP 服务启动一个使用独立环境的子进程，通过专属 stdin/stdout 管道通信，不增加监听端口。
- `/load` 和同一服务中的后续请求复用已加载实例。任务会话只保存文字动作历史；新会话清空历史，不重新加载模型。
- 每轮传入当前截图、原任务、完整文字经验和本任务先前模型决策。历史按作者格式转成编号动作行，例如 `1. click(x=0.300, y=0.400)`，不把未使用的槽位或推理耗时当作动作参数；所有历史步骤都保留，原始输出另存于审计的 `history_outputs`。官方读取器只接受单张图片，带图片的经验会明确报错；不静默丢掉附件。
- 保留作者的固定系统提示、用户模板和 assistant 槽位布局；提示词页只读。审计中的 `input.json` 记录实际原生消息，`outcome.json` 记录推理耗时、worker PID 和加载次数。
- 取消请求会等待当前原子前向计算返回并丢弃动作，保持已加载实例；超时或工作进程异常则终止该进程。服务进程树停止时连同其子进程清理。服务异常退出后管道关闭，worker 读到 EOF 退出。
- 每轮结束后释放 PyTorch 未占用的显存缓存，保留已加载权重和完整文字历史；推理异常同样尝试释放。审计记录推理峰值、回收耗时和回收后的 allocated/reserved 字节数。

## 动作边界

`click/select` 映射为左键点击，`swipe` 映射为 500ms 拖动，`press` 映射为明确支持的单键，`wait` 为 800ms。`scroll` 的 0–9 档映射为 5–50 行；这是桌面滚轮适配，不等于作者浏览器示例中每档 220 像素的距离。坐标仍按原图 0–1 归一化；执行后端继续校验范围与能力。

合并权重不能关闭 adapter 生成文本。因此 `type/open/answer` 返回人工接续提示，不发送空文本，不把 `answer` 视为完成证明；`back/home` 等没有明确桌面语义的动作被拒绝。独立完成核验返回 `unknown`。这是有限桌面适配，真实任务效果需单独验收。

## 本机验收（2026-10-28）

RTX 5070 Ti Laptop GPU，12GB 显存。通过实际 HTTP 客户端向服务提交作者的设置页面：第一个会话两轮，第二个新会话一轮。三次请求的 worker PID 相同、加载次数均为 1；第二个会话的 `previous` 为 `None`，没有继承上一任务动作。首次启动含文件校验与加载约 15.1 秒，预加载后的第一次服务响应约 1.22 秒，后两次约 0.44 / 0.41 秒。推理峰值 allocated 显存约 4.36GiB。

另验证服务关闭、进程树清理和再次预加载。验证仅作截图推理，没有向桌面发送模型动作，不代表实际任务成功率。原始记录位于 `artifacts/gui-decisions-resident-validation.json` 和数据目录的 `runs/local-gui/`。

## 长任务显存缓存回收（2026-10-28）

真实 Android 任务出现前四轮约 1 秒、第六轮起约 30–34 秒的推理延迟。第七轮界面显示的 34.30 秒是模型请求往返，其中推理占 33.82 秒。模型只加载了一次，但随历史长度变化，临时张量尺寸也变化；PyTorch 保留的 allocator blocks 累积，reserved 从首轮 5.50GiB 升至第七轮 13.72GiB、末轮 23.83GiB。Windows 进程计数器同时显示该 worker 使用约 10.74GiB 专用和 7.15GiB 共享 GPU 内存，出现显存压力下的性能下降。

worker 在模型加载后和每次单次前向结束后调用 `torch.cuda.empty_cache()`，只归还无占用的缓存块；不卸载权重、不缩短经验/历史，不改官方读取器。使用原任务的 12 轮截图、instruction 和 previous 字符串逐项一致地重放预测：单 worker、加载次数 1，推理 1.13–1.92 秒，客户端往返 1.36–2.44 秒。第七轮推理为 1.52 秒、往返 2.04 秒。运行中的 reserved 峰值 7.05GiB，全部 12 轮结束后的 reserved 均为 4.00GiB。77 项相关离线测试通过，包括成功与失败路径的回收。

此验收没有连接手机执行器，没有重放任何手机动作，也未自动恢复已停止的任务。原始请求、响应及逐轮对比保存在 `artifacts/slot-cache-20261028/replay/` 与 `artifacts/slot-cache-20261028/comparison.json`；修复已加载到本机常驻服务。

运行器现在在截图前显示当前阶段，手机截图长等待时每 5 秒显示进度，并向本地模型任务同步截图重试/恢复提示。规划、完成复核、模型等待后复查和结束留档的截图失败或取消时间都计入 `capture_ms`，错误以 `capture_failed` 事件留档。运行界面在折叠日志外显示截图等待，结束后分别显示截图、模型往返、动作和总耗时。仍沿用每次截图 60 秒、最多三次的读取策略，不把输入操作自动重试。
