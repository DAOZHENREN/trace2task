# Android / 红手指接入

当前实现复用 `run_chat_agent`、`ChatModelAdapter`、`ExecutionCore` 和原有截图/动作审计。
不占用 Windows 鼠标键盘，不向模型提供 ADB shell、应用启动、UI 树或游戏内部状态。
这是单指原型，不是已经验证的自动手游代理；桌面工作台提供 Android / ADB 和 MobileForge 入口。

## 工作台入口

1. 操作范围选「Android · 指定手机与应用」，执行后端会自动选中并锁定「ADB · 远程手机」。
2. 在红手指开启 ADB 通道。选择 Android 范围时，Trace2Task 自动刷新已连接设备并接入可用的红手指通道；仅一台在线时自动选中，多台时选择本次使用的手机。无需填写连接参数，也可手动刷新重试。
3. 从手机实际安装的可启动应用中选择授权应用；当前应用可自动识别。发现及应用读取不调用模型、不截图、不发送输入。
4. Android 策略选择「通用视觉代理 + ADB」或「MobileForge + ADB」。后者需填写固定版本源码目录，服务端会核验源码哈希。
5. 选择 Codex 订阅模型或视觉 API，输入任务，再确认设备与包名后启动。MobileForge API 仅接受本机端点，远端 GPU 可经本机 SSH 转发；不代表模型已经部署。

运行进入原有任务记录、截图、模型 I/O、动作回执和停止流程。每轮观察画面默认展开，可手动收起；执行回执单独默认折叠，轮次更新保留用户的展开/收起选择。默认预算为 160 个动作 / 40 分钟，可在任务区调整（1–500 个动作、0.5–120 分钟），任一预算耗尽即停止，明确标记任务未完成。
等待也计入动作预算；时间包含加载、截图和推理。时间耗尽通过现有停止路径阻止后续输入和迟到模型回答；已提交的 ADB 调用可能等待返回，不保证在整秒边界终止调用。不会自动续跑，也不会放宽断线、范围、无进展或手动停止保护。
Android 拒绝桌面经验、本地 GUI 专用模型、检查点恢复、混合桌面目标。选择应用可在任务确认后启动，不重置；运行期间断线即停，不自动重连。

### 已有连接发现（2026-10-21）

- 发现阶段通过 ADB smart socket 只读查询本机 5037、5038 和手动指定服务端口，并查询 RedFingerPro 进程持有的监听端口，不执行 `kill-server`。
- 选择 Android 范围及手动刷新时，对已发现但尚未接入的红手指通道各尝试连接一次。连接前重新核验端口仍属于红手指，再通过独立 5038 服务执行 `adb connect`。已有正常服务直接复用；被占用、版本不兼容或无响应的服务不覆盖、不重启。失败后保留手动刷新或选择通道重试，不循环重连。
- 设备以服务端口 + serial 区分；刷新保留仍在线的所选设备和仍安装的授权应用。未选择时仅一台在线会自动选中，多台时要求选择；offline/unauthorized 不可选。离开 Android 范围后取消刷新并拒绝旧结果，重进范围会重新刷新。任务提交仍进行原有绑定和前台预检。
- 特殊 ADB 路径、手动地址、应用包名和策略保留在折叠的「手动连接与高级设置」中。应用列表只用于宿主选定授权范围，不提供给模型作为游戏内部状态。
- Windows 通道发现依赖系统进程/监听端口元数据；无法读取时保留已有 ADB 服务发现及手动入口。

### 截图超时与有限重试（2026-10-26）

- 整屏 PNG 截图单独允许等待 60 秒；仅在截图命令超时时最多重试 2 次，共 3 次尝试，间隔 1 秒。截图等待、身份检查和间隔都计入任务总时间预算。
- 每次重试前通过只读 socket 查询原 ADB 服务，不以 CLI 查询触发服务启动或版本替换；要求原 serial 仍在线且 transport ID 未变，再核对原 boot ID、授权应用仍在前台及当前显示尺寸。截图返回后仍要通过前后状态和 PNG 尺寸检查，才归档并用于后续规划。
- 等待截图期间每 0.25 秒检查停止请求和时间预算；超时或取消时只结束本次取图的 ADB 客户端，不重启服务、不重连手机、不重发点击等输入。临时输出不会作为可用截图保存。
- 离线、身份变化、非授权前台、身份检查失败、截图命令报错或格式异常均不走超时重试。连续三次截图超时则停止任务，显示明确原因；运行日志记录重试和恢复。

验证：200 项相关回归测试通过，覆盖超时恢复、重试耗尽、设备/应用变化、ADB 服务失联或版本不兼容、停止与预算中断、输入不重发和完整代理流程。真实云手机只读检查中，注入第一次超时后，第 2 次尝试成功取得 1280×720 PNG，未发送手机输入、未调用模型；这是故障注入验收，并非复现自然网络故障。证据为 `artifacts/capture-retry-final-20261026.xml` 和 `artifacts/capture-retry-live-20261026-762c6158/result.json`。本次更新源码开发版，未更新安装版。

## 运行中追加指令与人工接管（2026-10-23）

首版支持任务工作台中的 **Android 通用视觉代理（Codex / 视觉 API）**，不支持 MobileForge 或本地 GUI 专用适配器。设备及经验准备完成后，运行详情出现「运行中干预」。

1. **补充指令 → 发送指令**：不改写初始任务，保留请求时间、唯一标识和实际进入的模型轮次；在下一次规划中作为当前用户指导。已发出的模型请求会继续等待，但其旧回答不执行；旧批次尚未执行的后续动作作废。
2. **我要接管**：先显示「正在交接 · 暂勿操作手机」。当前已准入的单个 ADB 动作可能自然结束；执行线程停止后续自动输入、尝试记录授权应用的接管前画面后，才显示「已暂停 · 可以手动操作」。不需要等模型回答才能确认暂停，也不在同一模型会话并发发新请求。
3. 手动操作完成后，回到本次授权应用，填写可选的**接管说明**，点击 **交还模型**。系统重新核对设备/应用，记录交还画面，再用新截图重新规划。不续用旧坐标或旧完成结论。不在授权应用内会保持暂停，须回到应用后显式重试交还；断线、设备重启等身份变化仍会终止任务。

暂停只停止 Agent 自动输入，不暂停游戏；原时间预算持续计时，动作预算不重置，停止按钮和 F9 继续生效。停止、预算耗尽或应用重启不会自动恢复，也不会补造缺失的交还截图。已结束的详情只供查阅。

每次运行最多 32 个干预请求、8 段接管，文字每条最多 2000 字。HTTP 回包丢失时，相同内容重试复用请求 ID，服务端不会重复追加。界面的「已加入请求 / 已收到回复」仅证明传递过程，不证明模型遵从。

截图保存为本次运行目录的 `interventions/takeover-N-before.png`、`takeover-N-after.png`，记录内容哈希和应用范围；现有运行档案同时保存指令、交接阶段与说明。只记录前后画面，**不录制中间点击、触摸或按键轨迹**。截图和说明会发送到本次选择的模型服务，界面在提交前说明这一点。

运行后的「提炼为经验」会额外提供全部已记录的接管前后图片和人工文字，不挤占原有最多 8 张模型观察图；校验来源路径、哈希和应用范围。编译结果要求引用 `[人工指令 N]` / `[人工接管 N]` 并说明人工贡献和证据局限，经验库标记 `human-assisted`，不把人工完成部分计为模型自主能力或独立成功。原父经验、哈希和反馈谱系仍保留；原样返回父方法仍标记无变化。精确操作录制不在本版范围内；现有经验提炼入口仍要求至少一轮有已交付动作回执，仅有计划或纯手动过程不会冒充模型执行经验。

## 持续摇杆与短程视觉纠偏（2026-10-23）

2026-10-26 调整：`navigate_to` 已从默认模型动作 Schema、提示词和能力清单中移除。默认执行后端也拒绝该动作；旧模型回答包含它时会作为格式不符退回重新规划。小地图控制器和历史记录仍保留，只有内部实验代码显式使用 `AndroidExecutionBackend(..., experimental_navigation=True)` 才能执行；工作台和模型均没有启用入口。正常任务使用 `joystick_move`、`camera_drag` 与新截图规划。

本次默认动作清理的相关回归共 217 项通过，覆盖默认拒绝、旧回答重新规划、实验控制器、共享执行流程、预算和人工干预。报告为 `artifacts/remove-navigation-targeted-20261026.xml` 和 `artifacts/remove-navigation-regression-20261026.xml`。使用模拟设备和模型，未发送实机输入；重启源码开发版后的新任务生效，未更新 `D:/Apps/Trace2Task` 安装版。

以下说明持续摇杆与保留的实验控制器：

- `joystick_move`：从摇杆中心迅速推到指定端点，保持该触点，最后抬起；不是沿途慢慢滑到端点的普通 `drag`。
- `navigate_to`（内部实验，默认不可用）：只在**稳定小地图**中追踪清晰、独特的任务标记，相对固定玩家锚点修正摇杆方向；接近目标时缩小推杆幅度，进入停止半径后释放触点。单次方向修正限制为 30 度。

`joystick_move` 的 `duration_ms` 为正整数，**没有固定的单次时长上限**。首轮和每次续轮规划都会提醒模型：清晰直路优先连续保持，例如 6～12 秒或根据可见空间选择更长时长；短段已显示稳定进展时增加下一段时长，避免沿同一路线反复只走 1～3 秒。示例不是最短或最长限制。靠近障碍、转弯或交互点时缩短；保持期间不重新观察或调整方向，不能假定未见区域畅通。`navigate_to` 每次仍最多 **1500 ms**。两者一次算原动作预算中的一个动作；内部 MOVE 是同一根手指的方向更新，不是额外的模型动作。每段结束后必须重新截图，旧批次后续动作和完成声明作废。预算默认 **160 动作 / 40 分钟**，沿用用户本次设置，包含准备、截图和推理耗时，不自动续跑、不重置计数。设备端实际保持时长会收紧至任务剩余时间。

`navigate_to` 参数为 `joystick{x,y,radius}`、`map_region{left,top,right,bottom}`、`marker{x,y,radius}`、`anchor{x,y}`、`stop_radius`、`camera_heading_deg`、`duration_ms`。坐标按原截图宽高归一化；三个半径均以截图短边为单位；相机朝向从小地图上方顺时针计算。小地图区域每边最多 512 像素，目标模板必须完整落在区域内。范围、标记、玩家锚点和相机朝向必须有可见依据。

这不是完整 3D 寻路：不绕障碍、不读取游戏内部坐标，不在运动时自动转相机，也不支持同时移动和释放技能。相机角度不明确时用短推杆或 `camera_drag` 后重新观察；没有稳定小地图时不用 `navigate_to`。MobileForge 原生策略尚未扩展这两个动作。

### 触点与中断保护

- 新动作第一次使用时，只上传本项目随包附带且经过 SHA-256 核对的短小辅助 JAR；不是安装 APK，不开启网络服务，不修改手机设置。普通点击、长按、滑动仍走原 ADB 路径。
- 每段独占一个进程、一个触点，START 指定的结束时间不能续期；只允许 START / MOVE / FRAME / KEEPALIVE / UP，不开放模型 shell。绑定 ADB 服务端口、transport ID、boot ID、前台窗口/Activity、旋转和显示尺寸。
- STARTED 确认允许最多等待 5 秒，兼容云手机回执延迟；等待期间仍检查停止和预算，设备原定释放时间不延长，不重发 START。
- 长于 1500 ms 的保持由主机发送心跳，设备每次重新检查绑定范围。心跳只确认主机仍在线，不延长本次动作的结束时间，不松开重按；最多一个心跳在途，避免积压指令掩盖断线。设备超过 1500 ms 未收到有效心跳就独立释放触点。
- F9、停止按钮、人工补充/接管、时间预算会独立请求 UP/EOF；取图使用独立工作线程，不阻挡释放。UP 不因范围或停止状态变化而被跳过；心跳超时、设备端错误或无法确认释放时终止整次运行，不重连、不盲重发。
- 目标丢失、视觉匹配歧义、距离变大、无进展立即松开。连续三段导航失败锁住新导航动作，须人工干预重新定位，不让模型自行重置失败计数。最初两张区域图仍太慢时，在 DOWN 前拒绝移动。
- `arrival_candidate` 只表示像素距离进入停止半径，不代表角色已到达正确 NPC、已经交互或已经获得奖励。回执仍是 `effect: unverifiable`，模型须用新截图核验任务结果。

导航中只传回小地图的无损亮度像素并保存 PNG，标注 `image_kind=minimap_luminance_crop`、裁剪区域、SHA-256、取图耗时、匹配结果、距离及释放状态，存于本次运行 `navigation/NNNN/`。原始整屏观察图保留，不把裁剪图冒充完整屏幕，也不把中间取图作为独立任务成功证据。

快速取图使用 [Android 10 的 SurfaceControl 截图接口](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android10-release/core/java/android/view/SurfaceControl.java)，编码和传输仅限所选区域。当前真实就绪验证为 Android 10；其他系统版本需要兼容性验证，不支持该接口时导航拒绝启动，不以盲推杆代替。

## 专用转镜头动作（2026-10-26）

Android 通用视觉代理（Codex / 视觉 API）增加 `camera_drag`。原有 `drag` 已能发送滑动，但没有相机专用的模型说明和观察边界。新动作连续滑动后抬起，支持横向转视角、纵向调整俯仰及斜向滑动；它不保持摇杆，也不承诺滑动距离对应某个角度。

只需 5 个参数：`start_x`、`start_y`、`end_x`、`end_y`、`duration_ms`。移除由模型重复填写的 `camera_region`，模型仍须根据当前画面选择避开控件和屏幕边缘的世界场景轨迹。坐标按**当前截图**宽高归一化到 0～1；执行器拒绝缺失或多余参数、越界坐标、零位移及转换到像素后不足一像素的轨迹。旧运行记录保持原样，新动作不再接受 `camera_region`。

首轮和每次续轮均说明：先选适度距离、约 200～500 ms 的短滑动，每次最多 1500 ms；根据下一张截图判断实际转向、灵敏度和是否反转，再决定后续动作。没有效果时重新检查区域和界面模式，不盲目重复。转镜头后必须根据新证据重新估计 `navigate_to` 的相机朝向，不能沿用旧角度。

- 一轮单独规划 `camera_drag`。若批次在它之前执行过任何动作，先结束批次重新截图，本次相机动作不发送。
- 滑动发送后结束批次，丢弃尚未执行的移动、点击及完成声明，重新观察再规划。一次滑动计入一个动作预算。
- 绑定本轮原始截图及哈希，执行前重新核验设备、前台、旋转和显示尺寸；已有移动触点时拒绝转镜头。移动与相机操作依次执行，不支持双指同时操作。
- 仍用一次 `adb shell input swipe`，不启动导航辅助程序。沿用普通 ADB 输入的停止和超时边界：已经发送的短滑动自然结束；结果未知或超时不重发，不承诺立即中断远端手势。
- 回执保留像素轨迹、时长及 `effect: unverifiable`，没有虚构的实际旋转角度。新截图和后续完成核验负责判断可见结果。

实现参考 [StarRailCopilot 的短滑动及观察循环](https://github.com/LmeSzinc/StarRailCopilot/blob/e2c7f0894fdea737805becbe02809ff01f47068e/tasks/map/control/control.py#L25-L96)，独立实现协议与校验，不沿用它的游戏角度标定常量；底层触摸语义依据 [AOSP Android 10 的 InputSwipe](https://github.com/aosp-mirror/platform_frameworks_base/blob/android10-release/cmds/input/src/com/android/commands/input/Input.java#L237-L278)：按下、沿路径移动、抬起。

## 当前能力与边界

- `click` → 点击；`hold_mouse` → 原地长按；`drag` → 单指滑动。
- `press_key: escape` → Android BACK；`wait` → 本地等待。
- `joystick_move` → 推杆后保持单触点，到时释放并重新观察；小地图反馈纠偏 `navigate_to` 仅保留为内部实验，默认不可用。
- `camera_drag` → 当前可见场景区域内的一次连续滑动，前后强制重新观察，不自动推断旋转角度。
- `joystick_move` 无固定单次时长上限，受任务剩余时间约束；其他带时长的动作最多 1500 ms。只支持左键语义，没有多指、摇杆与技能同时按、文本输入或应用切换。
- 绑定显式 serial、ADB 服务端口、transport ID、boot ID 和前台应用包名。
- 每次截图前后检查前台活动及旋转，PNG 尺寸必须吻合当前显示尺寸。
- 每次输入前重新检查；不自动重连、不重发结果未知的动作、不回退到桌面。
- ADB 返回成功仅记为 `effect: unverifiable`，不等同于游戏效果或任务成功。
- 前台检查与输入不是 Android 的原子事务；只有看到「已暂停 · 可以手动操作」后才接管手机，点击交还后停止手动操作。
- F9 停止后续操作。普通 ADB 输入仍会自然完成，单次调用超时上限 20 秒；新导航动作另有
  UP/EOF、设备端动作结束时间和 1500 ms 心跳超时释放机制。网络延迟下不承诺零延迟停止；触点不会跨动作保持。
- 登录、付费、下载确认和条款接受是模型提示中的禁区，不是页面级强制拦截器。
  未经人工复核，不应把它当作可无人值守的安全沙箱。

## Codex 模型等待与错误

Codex 执行规划的首次状态检查阈值为 300 秒（经验提炼为 120 秒）。到时没有完整回答会读取当前线程状态：
仍为 active 时继续等待同一请求，每 60 秒复查；检查本身最多 5 秒。idle 状态允许
再等 5 秒接收完成通知，查询期间已收到的完成或错误通知也会保留处理。非活动、无效
或无响应的状态查询会明确报错；提炼的硬时限和执行任务总预算仍约束这类等待。
CLI 可能在收到 HTTP 429 后，仅在结构化 stderr 中
记录重试等待时间，期间没有模型输出。通用视觉代理和运行经验提炼会识别这类限流，
按 CLI 给出的冷却期保留当前请求，自动继续；只扣除实际冷却时间，不消耗响应超时、
提炼硬时限或 Android 执行时间预算。普通无响应和未知原因的等待不会暂停任务预算。
不会另发重复的 `turn/start`，CLI 明确终止或额度耗尽仍会报告错误；停止/F9 始终有效。
长等待结束后，执行器重新截图；画面变化则丢弃旧计划，重新规划。界面显示冷却状态，
任务预算记录扣除的 `rate_limit_wait_seconds`。失败结果保存 `failure_category` 和
`model_failure_diagnostics`，原始 IO 审计保存 `codex_wait_status` / `codex_retry` / `codex_turn_error` 元数据，
不复制 stderr 中的原始文本或凭据。

2026-10-26 验证：相关回归共 371 项通过，覆盖 435 秒静默后同一请求返回、活动状态查询、
查询中到达的完成通知、无响应查询、硬时限、停止和过期画面拒绝，以及延迟 1.2 秒的
STARTED 回执不缩短或延长设备端 2 秒保持。报告：`artifacts/active-wait-joystick-20261026.xml`、
`artifacts/active-wait-shared-20261026.xml`。真实 Codex 的三轮纯合成测试把检查阈值临时设为
0.3 秒，三轮均查询到 active 后收到原请求回答，没有重复 turn/start；开阔直路选择了
12 秒、24 秒，近目标和墙壁场景选择中立摇杆停止。记录在
`artifacts/active-wait-joystick-live-20261026-network/result.json`。这是协议和提示词烟测，
没有向手机发送动作，不代表真实游戏任务成功。此前默认受限环境的测试未获得模型回答，
不纳入通过结果；正常网络权限下的同内容测试通过。正在运行的开发版须重启加载本次后端修正。

独立 `error` 通知中的不可重试错误、`systemError` 线程状态和已中断的轮次也会立即结束等待；
上下文耗尽、额度耗尽与网络连接故障分开分类。可重试通知和其他轮次的迟到事件不会误停
当前轮次。事件类型参见 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server#errors)，
具体 `willRetry` / 错误码以本机 CLI 生成的协议 schema 为准。

经验手稿支持填写提炼要求、直接编辑 Markdown 正文，以及提交修改意见生成独立修订稿。
直接编辑只在本机创建新草稿；按意见修订会把当前草稿、修改要求及已冻结的原始证据交给模型。
原稿、模型原文和源轨迹保留；新稿必须重新核对确认后入库，不自动执行。
人工参与编写的版本使用 `trace-compile+human-revision` 条件及 `authoring` 来源记录，
`human_confirmation_only=false`，不混入仅人工确认的 Trace Compile 条件。
